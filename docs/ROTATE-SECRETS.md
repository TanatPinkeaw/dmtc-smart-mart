# คู่มือหมุน (เปลี่ยน) Secret — DMTC Mart

คู่มือนี้บอกวิธีเปลี่ยนค่า "ความลับ" (secret) ของระบบให้ปลอดภัยตอนเปิดใช้จริง และควรทำซ้ำเป็นระยะ
เขียนสำหรับผู้ดูแลระบบ/รุ่นน้องที่มารับต่อ อ่านจากบนลงล่างทีละขั้นได้เลย

> **secret คืออะไร:** ค่าที่ถ้าคนอื่นรู้แล้วปลอมตัว/เข้าถึงระบบได้ เช่น กุญแจเซ็น token, รหัส DB, รหัสอีเมล
> ระบบนี้เก็บ secret ไว้ใน **environment variable** (env) ไม่ได้ hardcode ในโค้ด — ตั้งบน dashboard ของ
> host (Render สำหรับ backend) โค้ดอ่านผ่าน `backend/src/config/config.js` ที่เดียว

---

## 1. ทำไมต้องหมุน + หมุนเมื่อไหร่

- **ก่อนเปิดใช้จริงครั้งแรก** — ค่าใน dev/`.env.example` เป็นค่าตัวอย่าง (เช่น `dev-setup-key-...`) ใครก็เดาได้
  ต้องเปลี่ยนเป็นค่าสุ่มจริงก่อนใส่ข้อมูลนักเรียน/การเงินจริง
- **ทุก ~6 เดือน** — ตามรอบปกติ ลดความเสี่ยงถ้า secret หลุดโดยไม่รู้ตัว
- **ทันที ถ้าสงสัยว่าหลุด** — เช่น เผลอ push ขึ้น GitHub, ส่งในแชท, เครื่องที่เก็บไฟล์ถูกแฮก, คนในทีมที่รู้ค่าออกไป

---

## 2. รายการ secret ทั้งหมด + วิธีสร้างค่าใหม่

| secret | ใช้ทำอะไร | ผลถ้าหลุด | วิธีสร้างค่าใหม่ |
|--------|-----------|-----------|------------------|
| **JWT_SECRET** | กุญแจเซ็น token login (ทุกคน) | ปลอม token เป็นใครก็ได้ = เข้าระบบเป็น ADMIN ได้ | `openssl rand -hex 32` |
| **SETUP_KEY** | ปลดล็อก endpoint สร้าง admin/ล้างข้อมูล | สร้าง admin เอง/ล้างข้อมูลได้ | `openssl rand -hex 16` (หรือเว้นว่าง = ปิด endpoint) |
| **DB_PASSWORD** | รหัสเข้าฐานข้อมูล | อ่าน/แก้/ลบข้อมูลทั้งหมด | เปลี่ยนใน Aiven/DB console แล้วอัปเดต env ให้ตรง |
| **SMTP_PASS** | รหัสส่งอีเมล (App Password ของ Gmail) | ส่งอีเมลปลอมในนามร้าน | สร้าง App Password ใหม่ใน Google Account แล้วเพิกถอนอันเก่า |
| **CLOUDINARY_API_SECRET** | กุญแจอัป/ลบรูปบนคลาวด์ | ลบ/แก้รูปสลิป-รูปเข้างานได้ | กด "Regenerate" ใน Cloudinary dashboard |
| **LINE_CHANNEL_ACCESS_TOKEN** | ส่งข้อความ/ตั้งเมนู LINE OA | ส่งข้อความปลอมจาก LINE OA | ออก token ใหม่ใน LINE Developers Console |

> **คำสั่งสุ่มค่า** (รันบนเครื่องที่มี openssl — Mac/Linux/Git Bash บน Windows มีให้):
> ```bash
> openssl rand -hex 32
> ```
> ก็อปผลลัพธ์ (สตริงยาว 64 ตัวอักษร) มาวางเป็นค่า env ห้ามใช้ค่าที่เดาง่าย/ค่าเดิม

---

## 3. ขั้นตอนหมุน JWT_SECRET + SETUP_KEY (2 ตัวสำคัญสุด)

> ⚠️ **สำคัญ: เปลี่ยน `JWT_SECRET` แล้ว "ทุกคนจะถูกเตะออกจากระบบทันที" ต้องล็อกอินใหม่หมด** (token เก่าที่
> เซ็นด้วยกุญแจเก่าจะใช้ไม่ได้อีก) — เป็นเรื่องปกติ แต่ควรทำ **นอกเวลาขายของ** (เช่น หลังปิดร้าน) ไม่ใช่ตอน
> แคชเชียร์กำลังขายอยู่ ไม่งั้นบิลที่ค้างในตะกร้าจะหลุด

1. สร้างค่าใหม่ 2 ค่า:
   ```bash
   openssl rand -hex 32   # เอาไปใส่ JWT_SECRET
   openssl rand -hex 16   # เอาไปใส่ SETUP_KEY
   ```
2. เข้า **Render dashboard** → service `dmtc-mart-api` → แท็บ **Environment**
3. แก้ค่า `JWT_SECRET` และ `SETUP_KEY` เป็นค่าใหม่ที่สุ่มได้ → **Save Changes**
4. Render จะ **redeploy อัตโนมัติ** (~2 นาที) — พอ deploy เขียว = ค่าใหม่มีผล ทุกคนต้อง login ใหม่
5. **จดค่าใหม่เก็บไว้ที่ปลอดภัย** (password manager / กระดาษในลิ้นชักล็อก) — ห้ามเก็บในแชท/ไฟล์ในโปรเจกต์/GitHub

---

## 4. ตรวจว่าหมุนสำเร็จ

- [ ] เปิดเว็บ → ต้องเด้งให้ login ใหม่ (ยืนยันว่า token เก่าใช้ไม่ได้แล้ว = กุญแจเปลี่ยนจริง)
- [ ] login ด้วยบัญชีปกติได้ตามเดิม
- [ ] `GET https://<backend>/api/health` ยังตอบ `{"status":"ok"}` (ระบบไม่ล่มจากการ redeploy)
- [ ] (ถ้าเปลี่ยน SETUP_KEY) endpoint สร้าง admin เก่าเรียกด้วยคีย์เดิมต้องไม่ผ่านแล้ว

---

## 5. เช็คลิสต์ก่อนเปิดใช้จริง (ทำครั้งเดียว)

- [ ] `JWT_SECRET` เป็นค่าสุ่ม 64 ตัว ไม่ใช่ `your-secret-key-here-...`
- [ ] `SETUP_KEY` เป็นค่าสุ่ม (หรือเว้นว่างเพื่อปิด bootstrap endpoint)
- [ ] `DB_PASSWORD` เป็นรหัสยาวสุ่มจริง (ห้าม root/root หรือรหัสง่ายๆ)
- [ ] ไม่มี secret ตัวไหนโผล่ใน `.env` ที่ commit ขึ้น git (ต้องอยู่ใน `.gitignore` — `.env.example` เก็บได้เพราะเป็นแค่ค่าตัวอย่าง)
- [ ] จดทุก secret เก็บที่ปลอดภัย 1 ที่ (เผื่อคนดูแลเปลี่ยนมือ)

---

## 6. ถ้า secret หลุดขึ้น GitHub แล้ว (เหตุฉุกเฉิน)

การลบ commit อย่างเดียว **ไม่พอ** — ค่าที่เคยขึ้น public repo ถือว่า "หลุดถาวร" (คนอื่น clone/แคชไปแล้ว)
ต้อง **หมุนค่านั้นใหม่ทันที** ตามขั้นตอนข้างบน แล้วถือว่าค่าเก่าใช้ไม่ได้ตลอดไป
